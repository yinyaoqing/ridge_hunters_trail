# Ridge Hunter's Trail — Phase 6a 活的獵物（路線與新鮮度）v1.0

> 上游文件：`2026-09-02-boredom-remediation-roadmap-design.md` 的 Phase 6（R1 活的獵物）。
> 路線圖的 Phase 6 含三個子系統：①獵物移動＋線索新鮮度 ②驚動值 ③物種個性行為化。
> owner 裁定拆成兩半：**6a 做 ①與③**（物種個性的具體表現就是「路線怎麼走」，
> 拆開會把同一塊邏輯寫兩次），**6b 做 ②**。本文件只涵蓋 6a。

---

## 1. 這一階為什麼會動到地基

現在每一條線索都反向錨定在 `targetPos` 上：`makeClue` 先隨機取線索位置，再由
「該位置到目標」的幾何反推方向／半徑／距離，因此目標**必然**落在候選集合內，
`intersect(clues)` 保證非空且包含答案。這是整個遊戲的可解性地基。

**獵物一動，這個保證就塌了。** 線索仍指向舊位置，玩家完美推理、走過去，那裡什麼都沒有。
所以「獵物會動」不能實作成「每 N 步把 `targetPos` 挪一格」——那是拆地基，不是加功能。

本設計的核心主張：**把反向錨定廣義化，而不是拆掉它。** 錨點從「目標」變成
「覓食路線上的某個節點」，同齡線索的交集因此仍精確包含那一齡的位置。舊保證是新保證的
特例（單一節點、單一齡）。

## 2. 決策紀錄

| 分歧 | 裁定 | 落選項與理由 |
|---|---|---|
| 移動與可推理如何共存 | **覓食路線＋線索新鮮度** | 「只在交集區內游走」玩家感知不到，等於沒兌現狩獵；「只做驚動值」則追蹤一個會走的東西這件事根本沒發生 |
| 範圍 | **拆成 6a／6b** | 三個子系統綁一起是 25+ task 的分支，且若「獵物會走」本身不好玩，驚動值與行為規則都白做 |
| 移動節奏 | **走完剩餘路線就停在覓食地** | 「一直走到被逼近」沒有「牠最後會在哪」這個答案，押注只能比對結束那一瞬，而玩家無法控制何時結束；「只在判讀新線索時前進」懲罰的恰好是認真讀線索的玩家 |
| 視野內是否顯形 | **顯形** | 迷霧仍在，看得到牠時你已經很近了；這讓追蹤的最後一段可讀，而不是憑空猜 |

## 3. 架構

```
src/core/route.ts    路線生成、物種移動規則、依步數求當前位置   ← 純函式，可單元測試
src/core/types.ts    Level.targetPos → Level.route；Clue 新增 age
src/core/generate.ts 錨點改為路線節點；逐齡收斂檢查；幌子指派到有真線索的齡
src/core/session.ts  currentTarget(s)／isTargetVisible(s)；捕獲判定改用當前位置
```

`Level.targetPos` 目前有 44 處引用，散在 13 個檔案（`deduction`、`events`、`generate`、
`session`、`types`、`MapScene`、`ResultScene`、`RevealScene` 與五個測試檔）。
本階段最大的改動面就是這個掃除。**不保留 `targetPos` 當相容別名**——留著會讓下一個讀者
不知道該信哪一個，而「牠在哪」在這一階之後本來就不再是一個常數。

### 3.1 `src/core/route.ts` 對外介面

```ts
export type RouteRule = 'lowland' | 'highland' | 'cover' | 'straight' | 'doubling';

export const ROUTE_WAYPOINTS = 5;   // W0..W4
export const ROUTE_START_INDEX = 2; // 開局時獵物站在 W2
export const MOVE_EVERY = 12;       // 每 12 步前進一個節點

export interface Route {
  waypoints: Vec2[]; // 長度恆為 ROUTE_WAYPOINTS
  rule: RouteRule;   // 揭曉畫面用它說明「這個物種怎麼走」
}

export function routeRuleFor(creatureId: string): RouteRule;

// 依地形與物種規則走出一條路線。只在生成時呼叫一次，之後路線就是常數。
export function buildRoute(
  rng: Rng, terrain: TerrainType[][], elevation: number[][], size: number, rule: RouteRule,
): Route;

// 獵物在第 steps 步時的位置。走到最後一個節點就停住。
export function targetAt(route: Route, steps: number): Vec2;

// 覓食地——路線終點。只供揭曉畫面標示用；押注評分比對的是「結束當下」的位置（見 §6）
export function finalTarget(route: Route): Vec2;
```

## 4. 路線與物種規則

固定 **5 個節點 `W0…W4`**，獵物開局站在 `W2`。`W0/W1/W2` 是過去（線索留在那裡），
`W3/W4` 是未來。每 `MOVE_EVERY` 步前進一個節點，抵達 `W4` 後停在覓食地不再移動。

`targetAt(route, steps) = waypoints[min(2 + floor(steps / 12), 4)]`

節點間距 3–5 格（`straight` 規則加長、`cover` 規則縮短），由規則決定。求下一個節點的方式：
以當前節點為中心、在該規則的節距半徑上取一圈候選點，夾進圖內、剔除崖壁，
再依規則的評分函式取最佳者（`lowland` 取高程最低、`highland` 取最高、`cover` 取密叢優先、
`straight` 取與前一段方向夾角最小、`doubling` 前兩段照 `straight`、後兩段反向）。
全部候選都不合格時退回「離當前節點最近的可通行格」，保證路線一定生得出來。

### 4.1 五條規則、八隻生物

| 規則 | 生物 | 行為 |
|---|---|---|
| `lowland` | 霧絨鹿 | 沿溪谷低處走（下一節點取鄰域中高程最低者） |
| `highland` | 燼棘獸、稜脊獸 | 沿稜線高處走 |
| `cover` | 織叢雀、燈籽獸 | 貼著密叢走，節距短 |
| `straight` | 露躍獸、羽尾獸 | 一路直行、轉向最小，節距長 |
| `doubling` | 紗霧蛾 | 走出去再折返（`W3`／`W4` 折回 `W1` 一側） |

這是路線圖說的「物種個性從參數改為行為」：可觀察、可學習、可預測。玩過兩次就會學到
「紗霧蛾會折返，別直線外推」。

**`applyQuirk` 本階段不刪。** 路線圖說它該退場，但那八組生成參數就是現在的難度平衡；
在同一支分支裡既引入移動、又重調八隻生物的難度，出了事無從歸因。留給 6b 或之後，
且退場時要有對照測量。

## 5. 線索新鮮度，以及幌子第一次可以被推理排除

`Clue` 新增 `age: 0 | 1 | 2`，對應「更早／昨夜／今晨」。**反向錨定的程式碼完全不動**，
只是傳入的錨點從 `targetPos` 換成 `route.waypoints[age]`。

真線索分佈到三個齡，每一齡至少一條（分組推理需要），其餘偏向較新的齡。

### 5.1 幌子的矛盾

同齡真線索的交集必定非空且包含該齡位置。**幌子被指派到一個已經有真線索的齡**，
而它錨定在遠離該齡節點的 `decoyPos` 上——於是那一齡的交集**變成空的**。

玩家把線索按新鮮度分組，哪一組交集是空的，哪一組就有人說謊。這是可推理的排除，
不是數量投票——正是路線圖說的「干擾第一次可以被推理排除」。Phase 4 的靜音功能在這裡
第一次有了明確用途：靜音該組中的一條，看交集是否恢復非空。

### 5.2 收斂檢查必須改成逐齡

生成時的可解性檢查目前是 `intersect(clues, size).size <= maxIntersection`。
有了齡之後，全部線索的交集**本來就是空的**，這個檢查會無條件通過而失去意義。

改為：對每一個齡 `k`，`intersect(該齡的真線索)` 必須非空、包含 `W_k`，且大小
≤ `maxIntersection`；不滿足就對該齡追加 scent 線索（環形收斂最快），每齡上限 +3。

注意 `maxIntersection` 在高難度是 4，而分齡之後每一齡的線索數只有全部的三分之一，
用同一個門檻可能導致大量追加線索（線索一多，圖上到處是 token，反而更糊）。
**每齡門檻應獨立設定並以量測決定**，不要沿用 `maxIntersection` 就當作沒事——
實作計畫必須包含「每齡追加線索數的分佈」這項測量。

## 6. 捕獲、押注與可見性

- **捕獲**：玩家移動後先累加 `steps`，再以 `currentTarget(s)` 判定 `cheb <= 1` 進入 QTE。
  獵物換節點後若正好落在玩家旁邊，同樣在下一次移動判定時成立。
- **押注評分**：比對**結束當下**的位置（`currentTarget`），不是 `W4`。理由是誠實——
  「你停下來的時候牠在哪」是玩家真正該回答的問題；若改比對 `W4`，力竭在第 5 步的玩家
  會被拿去跟一個當時還沒發生的位置比對。預測的價值來自「要攔截就得算牠會走到哪」，
  而不是來自把評分基準推到未來。
- **可見性**：獵物進入玩家**當前**視野半徑內即顯形並隨步數移動。
  注意不能用 `s.seen`——那是單向累積的「看過的地」，而獵物會離開。
  新增 `isTargetVisible(s): boolean`，以 `cheb(player, currentTarget) <= visionRadius(...)` 判定。

## 7. 玩家介面

- **線索 token 依齡分濃淡**：越舊越淡。這是新鮮度最直接的表達。
- **HUD 新增新鮮度切換 chip**：今晨／昨夜／更早／全部，熱區逐齡計算。
  沒有這個切換，Phase 4 的圖層在多齡線索下會糊成一片而失去意義。
- **揭曉畫面畫出完整路線**：五個節點、連線、每個節點的齡，以及該物種的走法名稱。
  這是玩家學會物種行為的地方——沒有它，`doubling` 與 `straight` 對玩家而言只是隨機。

## 8. 可解性必須量測，不能猜

節距、`MOVE_EVERY`、剩餘節點數直接決定這遊戲還能不能贏。**這一階必須有一條掃描測試**：

跨 ≥300 顆種子，對每一顆計算「理想路線」的體力成本——出生角 → 起始蹤跡 →
再一條真線索 → 攔截點（依 `MOVE_EVERY` 推算玩家抵達時獵物所在的節點）——
並斷言在 **≥98%** 的種子上該成本不超過該難度的 `staminaBudget`。

先例：`ridgecrest` 的 `elevationBias` 就是這樣抓出來的——0.15 讓 11% 的首局在數學上
走不完，而型別檢查與既有測試全綠。**這類問題只有量測抓得到。**

## 9. 測試策略

`tests/route.test.ts` 釘住路線本身：

1. 節點數恆為 `ROUTE_WAYPOINTS`，全部在圖內、皆非崖壁
2. 相鄰節點之間的距離落在該規則的節距區間內
3. 每條規則都真的表現出它宣稱的偏好（`lowland` 的節點平均高程顯著低於 `highland`；
   `doubling` 的終點確實折回起點一側；`straight` 的轉角總和顯著小於其他規則）
4. `targetAt` 在 0 步時回傳 `W2`、在 `12k` 步時前進、超過路線長度後停在 `W4`
5. 同一組輸入永遠得到同一條路線（每日挑戰的決定性）

`tests/generate.test.ts` 擴充：

6. 每一個齡至少一條真線索
7. 逐齡交集非空、包含該齡節點、且 ≤ `maxIntersection`
8. 幌子所在的齡，其「含幌子」的交集為空——靜音幌子後恢復非空
9. 全部節點、線索、補給都從出生角走得到
10. 可解性掃描（§8）

場景層一如既往由 `npm run build` 加人工冒煙把關。

## 10. 明確不做

- 驚動值與慌亂痕跡（6b）
- `applyQuirk` 退場（見 §4.1）
- QTE 任何改動（Phase 7）
- Phase 7 的潛行決策序列、部分成功、異彩提前揭曉
- 獵物的移動動畫演出——本階段只要位置正確且顯形，演出留待手感調校

## 11. 風險

**最大風險是難度失控。** 這一階同時加入「答案會移動」與「線索分齡後每一齡的線索更少」，
兩者都讓推理變難。§8 的掃描是硬性門檻，但它只驗證「數學上走得完」，不驗證「人類玩得動」——
後者只有實測能回答，而本專案的實測欠帳已經三期。**建議 6a 落地後先實測再決定是否進 6b。**

次要風險：`targetPos` 的 44 處引用掃除會碰到五個測試檔與三個場景。場景層無法單元測試，
掃除時的疏漏不會被任何測試抓到。
