# Ridge Hunter's Trail — UI 優化設計報告 v1.0

> 狀態：**提案待審**。前置文件：`2026-08-31-gameplay-retention-optimization-design.md`（十項玩法提案，已認可）。
> 本報告盤點現有五個場景的 UI 實況，提出優化方向，並為十項玩法提案預留 UI 落點。經核准後與玩法提案一併拆解為實作計畫。

---

## 1. 現況評估

### 已做對的事（保留不動）
- 三套水墨配色循環＋恆定線索金光（`palette.ts`）——線索判讀性有制度性保障。
- 線索圖標為手繪感字形（足跡／漩渦／波紋），真假線索視覺完全一致，符合規格。
- 已判讀線索的幾何覆蓋層（錐形／圓域／距離環）畫在地圖上——推理的「外部化」做得好，玩家不用記在腦中。
- Help 彈窗用遊戲內實際圖形當圖例；字體載入有 fallback；儲存失敗有降級。

### 結構性問題（依嚴重度排序）

| # | 問題 | 位置 | 影響 |
|---|---|---|---|
| S1 | **固定 720×780 畫布＋FIT**：手機直向與寬螢幕都只是等比縮小 | `main.ts` | portal 平台過半流量是行動裝置；觸控目標縮到 <30px，違反 44px 最小觸標 |
| S2 | **標記功能依賴 Shift+點擊** | `MapScene.onPointer` | 觸控裝置完全無法標記——核心推理輔助在手機上不存在 |
| S3 | **沒有主選單／樞紐畫面**：Boot 直接進第一局 | `BootScene` | 每日挑戰（P1）、委託板（P8）、圖鑑入口、連勝顯示都沒有地方放 |
| S4 | **場景硬切無轉場**、移動瞬移、撿補給／踩線索零演出 | 全場景 | 回饋感（juice）缺位；峰終定律的「峰」做不出來 |
| S5 | **CodexScene 版面寫死**（`y = 138 + i*68`、按鈕 y=736） | `CodexScene` | 8 種剛好塞滿；規格書路線是 12→20 種，且研究度／品質徽章（P2/P3）無處可放 |

## 2. 逐場景優化提案

### U1 全域基礎：響應式與觸控（對應 S1、S2）
- 縮放改 `Phaser.Scale.RESIZE`＋佈局函式依實際視窗重排；地圖區以「可用短邊」計算 cell，HUD 依寬度斷點（<560px 收合為單行＋icon）。
- 直向手機：HUD 移到頂部單行，地圖滿寬，操作提示改首次浮層。
- 標記改為**長按（350ms）**切換，桌面保留 Shift+點擊；HUD 加「標記模式」切換鈕（點一下後進入標記模式，再點還原），兩種路徑並存。
- 所有可點元素最小命中區 44×44px（現況：語言 chip 30px 高、關閉鈕已 40px）。
- 估時：2–3 天。**此項是其他所有 UI 工作的地基，最優先。**

### U2 營地（Basecamp）主選單（對應 S3；承載 P1／P8）
- 新場景 `CampScene`：Boot → Camp。構圖：山稜線剪影＋營火微光（程式繪製，延續水墨方向）。
- 內容：
  - 「上山追蹤」主按鈕（進主線，顯示目前局數）
  - 「今日行蹤」每日挑戰卡（日期＋天氣圖標＋連勝徽章＋完成勾）
  - 委託板：3 張輪替委託小卡（P8）
  - 「生態圖鑑」入口（顯示 n/8 進度點列）
  - 語言切換／玩法說明移到此處，Map HUD 減負
- 心理學：回訪時第一眼看到「連勝」「未完成委託」「圖鑑缺口」三個 Zeigarnik 鉤子，再開始遊玩。
- 估時：2 天（不含每日挑戰邏輯本體）。

### U3 回饋層（對應 S4；規格書 §8.1「QTE 手感為成敗關鍵」的 UI 面）
| 時刻 | 現況 | 提案 |
|---|---|---|
| 移動 | 瞬移＋redraw | 80–120ms tween；體力扣減以 `-1`／`-2` 浮字沿途淡出 |
| 踩到線索 | 覆蓋層直接出現 | **揭示演出**：錐形 200ms 掃開／圓域漣漪擴散／距離環脈動一次＋輕音效——這是核心 aha 時刻，值得花預算 |
| 撿補給 | 圖標消失 | 綠色 `+10` 浮字＋體力條閃一下 |
| 低體力 | 無警示 | 體力 <25%：條轉橘紅＋緩慢脈動（不加音效轟炸，家庭向） |
| QTE 命中／失手 | 只有點數變化 | 命中：弧區金光爆點＋擊中音；失手：畫面 60ms 微震＋弧區轉灰 |
| QTE 結束 | 500ms 硬切 | 成功：剪影從霧中亮起再入結算；失敗：剪影淡出（溜走方向感） |
| 場景切換 | `scene.start` 硬切 | 全域 240ms camera fade（黑 → 場景），成本極低 |
- 估時：3 天。動畫全部尊重「一次性、短促」原則，不做循環騷動。

### U4 資訊層：降低認知負荷
- **地形成本可見化**：桌面 hover 格子顯示高亮＋成本角標（`1`／`2`）；觸控改為 HUD 常駐迷你圖例（四色塊＋成本數字）。現況玩家必須記住 thicket/rock 耗 2 體力。
- **線索已讀狀態**：已判讀的線索 token 加金色小勾（或降飽和），一眼看出哪些還沒踩。現況 token 永遠同貌。
- **操作提示自動退場**：`hud.hint` 在玩家完成 3 局後預設隱藏，「?」仍可叫出 Help。
- 估時：1.5 天。

### U5 圖鑑改版（對應 S5；承載 P2 研究度／P3 品質／P9 變種）
- 列表改為可捲動容器（拖曳＋滾輪），行高提高至 84px 容納新元素。
- 每行結構：剪影 ▸ 名稱＋品質墨章（銅/銀/金）▸ 描述 ▸ **研究度進度條**（P2 筆記碎片累積，里程碑刻度）▸ 收錄次數。
- 未發現生物：以**模糊剪影輪廓**取代 '?'（能認出「有這一種」但看不清）——收集渴望比純問號更強（圖鑑 teaser 慣例）。
- 為異彩變種（P9）預留：行右側小星位，發現後點亮。
- 估時：2 天。

### U6 結算改版（承載 P2 掉落／P3 品質揭曉／P5 押注／P1 分享卡）
- caught：品質揭曉演出（墨章蓋印動畫，銅→銀→金停在結果）為峰終之「峰」；下方 8 格圖鑑進度點列取代純文字計數（endowed progress 可視化）。
- escaped/exhausted：加入「觀察筆記 +n」掉落演出（P2）——把「失敗畫面」轉為「小收穫畫面」，文案已有「山林守住祕密」的溫柔基調，視覺跟上。
- P5 押注選擇：結算主按鈕位置改為雙卡（「安全歇腳」實心金／「乘勝續追 ×1.5」描邊）＋風險說明一行。
- 每日挑戰結算：emoji 成績卡預覽＋「複製分享」鈕（P1）。
- 按鈕補 hover／pressed 狀態（描邊增亮／內縮 2px），現況零狀態回饋。
- 估時：2–3 天（分批隨對應玩法提案實作）。

### U7 新手引導互動化（portal「3 分鐘上手」指標）
- 首局改為腳本化引導取代一次性 7 條圖例彈窗：
  1. 高亮最近的線索 token：「走過去看看」
  2. 踩上後：線索揭示演出＋一句解讀（「牠往這個方向去了」）
  3. 第二條線索揭示後：提示「兩個範圍重疊的地方」＋短暫高亮交集區一次（僅首局，不違反「UI 不強制提示正解」——之後永不再提示）
  4. 逼近觸發 QTE 前：一行預告
- Help 彈窗保留為參考手冊（「?」開啟）。
- 估時：2 天。

## 3. 視覺系統補充

- **中文字體斷裂**：Marcellus（拉丁展示字）中文 fallback 到系統字，標題中英混排風格不連續。建議：中文標題明確走 `"Noto Serif TC", "MingLiU", serif` 優先序，並在 `FONTS` 分 `displayLatin`／`displayZh`，由 i18n locale 選用。零成本（不打包字型，維持 Poki 8MB 空間）。
- **數字統一 tabular**：體力／局數／計數字型已是等寬友善的 Karla，維持；浮字動畫也用同字體。
- **色彩語意固定化**：金＝線索／主行動、發光色＝生物／氣味、橘紅（`mark`）＝玩家標記與警示、綠＝補給／恢復。新 UI（研究度、品質、委託）一律從既有 `Palette` 取色，異彩變種另定一個 `iris` 色欄位加入三套循環。

## 5. 明確不做

- 不引入 DOM/HTML 疊層 UI（維持單一 Phaser 渲染管線與 itch.io 打包單純性）。
- 不打包字型檔、不加外部素材（維持零成本與 8MB 優化空間）。
- 不做常駐循環動畫與粒子雨（家庭向＋低階裝置效能＋水墨留白的美術方向）。
- 不做小地圖／自動尋路（推理閱讀地圖本身就是玩法）。
